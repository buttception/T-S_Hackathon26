Adaptive CGF Trainer: how the project fits together

An instructor allocates a crew, the simulator runs it while an engine adapts the computer-generated forces, a report is written, and the trainee's profile is updated for next time. This map follows the repo buttception/T-S_Hackathon26 as of 470774f, folder cgf-demo/.

JL: allocation, hand-off, competency update Devin: simulator and adaptation Glenda: report and history Eevee: look and feel Stored in the browser

The flow of one training session

Read left to right. The dashed line is the loop that makes the next session different: the update step writes the profile, and the allocation page reads it. The runtime gets each seat's profile in the link-init message.

4 pages in the main loop 2 read-only views 3 signals behind each CGF change: live, history, team 0 servers: it all opens from file://

How this was checked. A script read every tracked file and counted a file as used when another file's text names it, starting from the six pages plus config.js. That finds files nothing refers to. It cannot prove a referenced file is exercised at run time: a script that is loaded but never called would still count as used. Node test files (tests/**/*.test.js) are run by node --test and are not orphans.
